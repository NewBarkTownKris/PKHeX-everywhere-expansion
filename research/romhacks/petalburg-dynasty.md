# Pokémon Petalburg Dynasty 1.10.0 — investigation

The supplied ROM has SHA-256 `7712f721cfe961bd8b8f1017dacaa62f0bb085ce534c0680dfb46171b1d943f2`, mGBA CRC `A360B05C`. The 131,088-byte `.sa2` passed sector and Pokémon checks under the generic expansion 1.17.1 source profile; it contains six party and three boxed records. A no-op output was byte-identical and an isolated nickname edit reopened with every unrelated Pokémon unchanged; a private edited copy loaded in the supplied ROM and displayed the changed name.

This establishes structural similarity, not complete compatibility. The supplied party includes a custom MissingNo. entry whose interpreted native species is outside official species IDs. The site must not export it as a real Pokémon. Other species, forms, move/item IDs, personal data, met locations and hack mechanics need revision-specific verification and a real-species filter before promoting this title to supported. Save-state compatibility is unverified. No ROM, save, state or private record belongs in the repository.

## Experimental read-only recovery

The local next build now offers selected battery and exact-ROM-CRC mGBA party/PC extraction to PK6/PK9 for this revision. The supplied save produced eight portable files and skipped its one custom species. An edited private save and its mGBA state agreed byte-for-byte for all eight recognized records; portable checksums, trainer IDs, species and archive contents were checked. Invalid save sectors and state pointers were rejected. One sample does not validate every species, save configuration or game mechanic.

The exact ROM’s species table begins at `0x746F14`, stride `0x108`; 1,068 source IDs matched an official base species and the existing expansion mapping by name. Only these base-species matches are eligible. Its move table begins at `0x7261F8`, stride `0x44`; 876 unique source-name candidates were compared with official move names, and a Pokémon is portable only when the source name and expansion mapping agree for every move. Unknown/custom species, alternate forms and eggs are skipped; unsupported moves are retained as native-only with an error.

The record layout is structurally compatible with the existing expansion 1.17.1 reader in this sample. Portable files remove held items, substitute Poké Balls, leave met location unknown and use standard ability/gender assumptions. Original native fields and encrypted records are retained. Shininess uses the compatible source profile; other hack-specific mechanics are not guaranteed. Live party count, party and storage pointer were observed at `0x02036DDC`, `0x02036DE8` and `0x03005464` for the supplied ROM. Implementation is `Historic/PetalburgRecovery.cs` plus the revision-specific generated candidate table. No ROM or user save is distributed.
