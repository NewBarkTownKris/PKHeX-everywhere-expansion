# Pokémon My Ass — limited VBA party research

**Status:** local next-build, read-only native party-record recovery from explicitly selected revisions only; conditional PK6 export; read-only battery save export for the supplied revision (party checked with a game-created save; PC covered by synthetic tests only). Three supplied VBA 9 states contain 5, 5 and 6 checksum-valid player party records; opposing battle Pokémon were excluded using the verified player party count and address. The FireRed header is shared with unrelated games.

ROM SHA-256 fingerprint(s): `04d0ed202747464a34fd3d51c6f060346cd60547afc5ebc27246123efeace857`. Source species name tables and their conservative derived allowlists: [my-ass](../../src/PKHeX.Everywhere.RomHacks/Historic/vba-my-ass.json). The allowlist requires the same official name and original Generation III internal species ID. Unmatched IDs, including custom species, are skipped. Name/ID agreement is necessary evidence, not proof of unchanged stats, forms, abilities or evolution semantics; the ROM header in a state cannot establish the exact matching ROM.

The [VBA reader](../../src/PKHeX.Everywhere.RomHacks/Historic/VbaParty.cs) validates version, length, game header, party count and Gen 3 record checksums. Its native `.bin` records retain the original OT, ball, shiny-related PID/OT, moves and met fields; these fields are retained in metadata; eligible records can additionally export to PK6 with an unknown met location and standard ability/shiny assumptions. Species, moves and items use conservative name matches, not proof of matching mechanics. Only standard Poké Balls are presently accepted for portable export. Game-specific ball, shiny, item, move and location behavior has not been verified. Do not assign standard routes or portable origins merely from numeric ID. The party must be independently checked against real gameplay and future tests must include boxed Pokémon and more species.

See [VBA state research](../formats/vba-sgm.md) and [the synthetic checks](../../src/PKHeX.Everywhere.ProfileChecks/VbaChecks.cs). Private supplied states are not in this repository.

## Battery saves

A fresh in-game save from the supplied ROM was generated and reopened in mGBA. It contains a checksum-valid level-5 Cyndaquil at native ID 155; the conservative exporter produced PK6 with matching trainer/ID, species, moves, IVs and EVs, retaining the original party record and source met ID. The in-game ROM identifies the starter as Cyndaquil. A synthetic FireRed-format save checks a party member plus Box 2 Slot 3, RTC footer handling and correct archive positions; no real occupied-PC save has yet been validated. [HistoricGen3.cs](../../src/PKHeX.Everywhere.RomHacks/Historic/HistoricGen3.cs) validates slots and sector checksums, and [VbaParty.cs](../../src/PKHeX.Everywhere.RomHacks/Historic/VbaParty.cs) handles the profile's read-only projection. Filename and shared FireRed header do not identify a revision; user selection must be correct.

## mGBA state, exact supplied build

The exact supplied ROM CRC32 is `1DED7E51`. Its fresh, game-generated mGBA state and in-game save agree for the Cyndaquil party record. This build uses `0x02024029` for party count, `0x02024284` for party, the SaveBlock2 pointer at `0x0300500C` for trainer name, and PC storage pointer at `0x03005010`; storage records begin four bytes after that pointer. These addresses are game-build-specific. [VbaParty.InspectMgba](../../src/PKHeX.Everywhere.RomHacks/Historic/VbaParty.cs) uses the [mGBA container decoder](../../src/PKHeX.Everywhere.RomHacks/Expansion/MgbaState.cs), checks CRC, pointers and record validity, and applies the same conservative PK6 conversion. Real occupied-PC coverage is still missing; a synthetic state tests box 2 slot 3 and invalid pointer rejection.

## Source location investigation

A candidate FireRed-style location-name table at ROM offset `0x3F1CAC` has 92 of 109 entries matching retail names at the same numeric ID after case/punctuation normalization. For example IDs 88 and 101 read Pallet Town and Route 1. This is not proof that every map or encounter retains retail semantics; region and location remapping are still unverified, so PK6 output remains unknown rather than asserting Kanto. The audit also shows why this conclusion must not be generalized to either Rijon revision.
