# Pokémon Recharged Yellow — investigation

The supplied ROM has SHA-256 `442c38ee4ac598795107eee730bdd4b0b59148c0faec3a4def21af8396703da9`, CRC `DEF0F69E`. A private copy of the supplied 131,088-byte save loaded in the supplied ROM. Generic PKHeX detection reports SAV3RS with valid checksums and byte-identical no-op, but this does not validate its Pokémon layout or game-specific field mappings. The current expansion 1.17.1 profile rejects the save.

PokeDaisy’s `scripts/gen_recharged_yellow_tables.py` describes revision-specific species, move, item and location tables; its local notes identify multiple ROM revisions and a migrated save. Use these as research leads, with attribution, and independently validate the supplied ROM/save and real species before producing portable files. Custom and ambiguous species must be skipped. No export support is claimed yet; originals remain untouched.

The supplied BPS patch has a valid patch CRC, and its target CRC `DEF0F69E` matches the supplied ROM. The patch source CRC is `1F1C08FB`; this check establishes the target revision without redistributing the ROM.

Live-state comparison using PokeDaisy’s 1.9.7 party address `0x0203855C` and count `0x02038559` found four party records in game, each byte-for-byte present in the original save starting at file offset `0x14044` with valid encrypted-record checksums. Generic PKHeX’s apparent count was five, a mismatch that demonstrates why its generic auto-detection is unsafe here. The live state and actual save slot must drive a dedicated read-only reader; validate source species, moves, PC and other mappings before export.

## Experimental recovery implemented

The local build now has an explicitly selected 1.9.7 battery reader and exact-CRC mGBA party/PC reader. The saved party count is at SaveBlock1 `0x3B` and its six 100-byte entries start at `0x44`; PC storage uses the standard 14-box layout. The active complete 14-sector slot is verified before reading. All four party and both boxed records in the supplied save matched the live state byte-for-byte, and six PK6 files and the archive passed checksum/identity checks. Corrupt save slots and out-of-range state pointers were rejected. One save and its matching state do not establish behavior for all game revisions or all Pokémon.

The source revision’s species names use Gen 3 internal IDs: 386 matched official names and original IDs. Its 13-byte move-name table at `0x7738D8` yielded 350 exact official-name/ID candidates. Unknown species/forms, eggs and unrecognized moves are skipped or retained only as native records. Pokémon use an FR origin and a Kanto regional approximation rather than a claim of an exact capture location. Held items are removed, balls are replaced by Poké Balls, and ability, gender, growth and shininess use documented standard assumptions. Source bytes and original IDs remain in metadata. No retail legality is implied. Implementation: `Historic/RechargedRecovery.cs`, `Historic/recharged-yellow-tables.json`, and `ClassicRecovered` conversion. PokeDaisy’s `gen_recharged_yellow_tables.py` and `NativeReader.kt` informed addresses and table shapes; no ROM assets are included.
