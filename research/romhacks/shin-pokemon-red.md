# Shin Pokémon Red 1.24.5 — save investigation

**Status:** local read-only live-party PK1 export from the supplied mGBA state for this exact ROM; underlying inherited PKHeX Gen 1 reader also recognizes one supplied 32 KiB battery save. This is not a claim that save editing, PC extraction from states, every revision, every game-specific option, or the web upload/download flow is validated. The corresponding supplied ROM SHA-256 begins `f57d40f4ef0f`. The patch filename and [project's 1.24.5 documentation](https://github.com/dotmatrixgirl/shinpokered/blob/master/README.md) identify that version; the file name alone cannot identify arbitrary saves.

## Evidence

The supplied save opens as a checksum-valid `SAV1` via `SaveUtil.GetSaveFile`, with six party and five boxed records. A copy loaded in mGBA with the supplied ROM; the six displayed party nicknames and levels matched the reader, and a first Pokémon status screen was inspected. A PKHeX no-change save round trip was byte-identical. Eleven PK1 records were created and re-read using PKHeX; species, trainer name and ID, nickname, moves, and DV-derived shiny result matched the reader. This is one user save, not a synthetic substitute; do not include the save, records, names or ROM in the repository. The local reproducible check lives outside the web repo at `misc-save-recovery/ShinRedChecks`.

## Mapping and limitations

The observed party and box use real Gen 1 species and standard species identifiers as interpreted by PKHeX; this observation does not independently prove the full roster or every move. PK1 preserves the original Gen 1 data; no fabricated catch location or Poké Ball is added because Gen 1 does not store them per Pokémon. The project's documentation says shininess is indicated when DVs satisfy the Gen 2 shiny rule. PKHeX also interprets Gen 1 DVs for shininess, but no shiny specimen was available to compare in-game. This sample had no shiny records. The game's added options and mechanics may use otherwise unused save bytes; edited-save round trips have not been tested and should not be advertised as supported. Newer-format conversion has not been checked for this title. The supplied `.ss1` is an mGBA PNG state, with `gbAs` and `gbAx` chunks; it successfully loads with the supplied ROM. The new GB state reader validates PNG chunk CRC, decompresses a bounded 0x11800-byte core, checks core version `0x00400003` and ROM CRC `878032D3`, and reads the live English party at core offset `0x5563` (404 bytes). It emits individual PK1 files, with no PC export. A private real state produced six Pokémon whose identities matched the battery save; synthetic tests cover PK1 export, a bad ROM, invalid count and GBA discrimination. Implementation: `Historic/MgbaShinRed.cs`; dispatcher: `Engine.Host/StateExports.cs`.
